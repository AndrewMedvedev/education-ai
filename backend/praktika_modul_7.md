## 4. Теоретическая справка

Перед выполнением работы необходимо повторить материал Модуля 7:

- **Управление дефектами (Defect Management)** — системный процесс регистрации, отслеживания, анализа и закрытия дефектов.
- **Баг-репорт** — формализованное описание дефекта с обязательными полями: ID, заголовок, шаги, фактический/ожидаемый результат, окружение, Severity, Priority, вложения.
- **Severity (Серьёзность)** — техническая степень влияния дефекта: **Blocker, Critical, Major, Minor, Trivial**.
- **Priority (Приоритет)** — бизнес-важность исправления: **High, Medium, Low**.
- **Severity ≠ Priority**: опечатка на главной странице = Minor Severity + High Priority.
- **Жизненный цикл дефекта:** New → Assigned → Open → Fixed → Retest → Verified → Closed; дополнительные статусы — Rejected, Deferred, Reopened, Cannot Reproduce.
- **Метрики тестирования:**
  - **Test Coverage** = (покрытые требования / всего требований) × 100%;
  - **Pass Rate** = (пройденные ТК / все выполненные) × 100%;
  - **Defect Density** = количество дефектов / размер модуля;
  - **DRE (Defect Removal Efficiency)** = (дефекты до релиза / все дефекты) × 100%;
  - **Defect Leakage** = дефекты, пропущенные в прод;
  - **Reopen Rate** = % переоткрытых дефектов;
  - **MTTR** = среднее время от обнаружения до закрытия;
  - **Defect Aging** = время в открытом состоянии;
  - **Bug Distribution** = распределение по модулям, Severity, типам.
- **Agile-манифест (2001):** люди и взаимодействие, работающее ПО, сотрудничество с заказчиком, готовность к изменениям.
- **Scrum:** спринты 1–4 недели, роли (PO, SM, команда), события (Planning, Daily, Review, Retrospective).
- **Kanban:** непрерывный поток, WIP-лимиты, время цикла.
- **Acceptance Criteria** — критерии приёмки User Story в формате Gherkin (Given/When/Then).
- **Definition of Done (DoD)** — чек-лист готовности инкремента.
- **Test Retrospective** — анализ процесса тестирования в спринте.
- **Shift-left** — раннее вовлечение QA (анализ требований, refinement).
- **Антипаттерны:** «Это не баг, это фича», игнорирование Minor, долгое нахождение в Open, неполные баг-репорты, массовое закрытие без проверки.
- **Российские инструменты:** YouTrack, Яндекс.Трекер, Kaiten, Test IT, Allure TestOps.
- **Связь с бизнес-целями:** DRE и Defect Leakage → снижение инцидентов; Cycle Time → ускорение TTM; юзабилити → удовлетворённость; % автоматизации → сокращение затрат.
