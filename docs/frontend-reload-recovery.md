# Восстановление frontend после reload

## Карта состояния

| Область                | Источник истины и восстановление                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Курс, модули, уроки    | GET API после холодного старта; URL задаёт адресуемые ID, независимо от каталога                                                              |
| Несохранённый редактор | Версионированные локальные дельты `editorDraftStore`, поверх свежих серверных сущностей                                                       |
| Авторизация            | Существующий `aicolab_session`; единственный refresh singleflight на контекст, без дублирования токенов в draft-хранилищах                    |
| Identity/permissions   | Повторная проверка через API; кешированные права не используются как доверенный источник                                                      |
| Прогресс               | Существующие `progressService`, `useCourseProgress`, `useMyCoursesProgress`; локальные legacy `App.completed*` не являются прогрессом ученика |
| AI                     | Ограниченная локальная история + `chat_id`; черновики ввода; для запущенных генераций возобновляется GET-наблюдение                           |
| DnD                    | Существующий формат черновика, scoped по владельцу; синхронный flush готового локального snapshot при завершении страницы                     |
| Тема/UI                | Существующие ключи, версии и миграции; безопасный адаптер и проверка same-version значений                                                    |
| Прокрутка              | Ожидание достаточной высоты контента, отмена при вводе пользователя; максимум 15 секунд                                                       |

## Подтверждённые причины

1. `frontend/src/utils/routeState.js`: вложенные ID разбирались только при наличии курса в памяти. `frontend/src/course/courseState.js` затем заменял явно запрошенную, но ещё не загруженную сущность первым элементом.
   На версиях этих файлов из `git show HEAD:…` падают 33 из 49 новых pure regression-проверок; на рабочих версиях проходят все.
2. `frontend/src/App.jsx`: маркеры loaded выставлялись до успешного GET. Параллельные загрузки модулей конкурировали; `Promise.all` мог отбросить результаты успешных соседей. Поздняя страница каталога могла удалить отдельно загруженный курс.
3. `frontend/src/stores/editorDraftStore.js`: правки существовали только в памяти. Безусловное удаление edit после save также могло удалить более свежую правку той же сущности.
4. `frontend/src/utils/api.js`, session/permission stores: ошибки refresh и асинхронные ответы требовали различения временной ошибки и невалидной сессии, singleflight и привязки к контексту. Проверки реальных модулей воспроизводят сетевые ошибки, истечение токена, поздние 401 и смену пользователей.
5. `courseService`/`progressService`: кеши и выполняющиеся Promise не были изолированы контекстом. Изоляция только на уровне компонента была недостаточна.
6. `agentStore` сохранял только интервьюеров; inputs и часть состояния Creator терялись. Отложенная запись DnD могла потерять последние изменения. Однократный RAF прокрутки не ждал асинхронный контент.
7. Стандартный persist UI/theme мог выбросить ошибку записи прямо из route effect. Новые тесты реальных stores до исправления воспроизвели 12 падений при quota/unavailable/malformed storage.

Отсутствие nginx SPA fallback причиной не объявляется: существующий `try_files` не менялся.

## Правила восстановления и сохранения

- `frontend/src/hooks/useCourseDetails.js` и `frontend/src/course/detailLoader.js`: per-key idle/pending/success/error, дедупликация GET, успешный пустой ответ считается загруженным. Ошибки повторяются кнопкой; успешные соседние результаты сохраняются. Старый scope инвалидируется, включая A → B → A и StrictMode cleanup.
- Каталог и детали не удаляют друг друга; каталог отображает только ID своей страницы. Добавлен alias `/course/:courseId/lessons/:lessonId`, который ранее распознавался парсером, но не маршрутизатором.
- В App хранятся серверная база и отдельные дельты. Каждый render накладывает актуальные дельты: поздний GET не уничтожает введённое. Reload не отправляет PUT.
- Save сериализуется; перед записью выполняется свежий GET. Если изменяемое поле отличается и от исходного, и от локального значения, запись блокируется как конфликт. Удалённая сущность не создаётся заново; draft остаётся. Ошибки сохраняют draft. После полного успеха CAS-acknowledge удаляет только сохранённый snapshot либо перебазирует более свежие правки. Discard возвращает серверную базу, а не старый кеш исходных значений.
- Пользовательские локальные данные изолированы по подтверждённым user/membership/organization и сущности. Неподписанные старые глобальные записи не присваиваются вошедшему пользователю. Контекст сессии защищает поздние callbacks; App remount при смене контекста исключает показ прошлого локального дерева.
- Runtime loading, AbortController, таймеры и File не сериализуются. Сохраняются только метаданные вложений; при отсутствии исходного файла UI просит выбрать его снова. Прерванная DnD-загрузка остаётся прерванной и при повторном reload.
- История всех пяти используемых AI-типов сохраняется существующим bounded persist (30 диалогов, 200 сообщений). Reload не повторяет POST или применение AI-предложения. Backend поднимает chat history при следующем POST с тем же chat_id; отдельный GET истории не найден и не добавлялся.
- При ошибках storage важные черновики остаются в памяти, показывается предупреждение. Без доступной записи на диск обещать восстановление после закрытия вкладки нельзя.

## Проверки

Инфраструктура репозитория до изменений: Python-тесты backend; frontend test-script отсутствовал.
Добавлены Node `node:test` без DOM и дополнительных unit-зависимостей, esbuild для загрузки реальных JSX/store-модулей с управляемыми транспортом/lifecycle, и Playwright как dev dependency для настоящего браузера.

Основные файлы проверок:

- `frontend/src/course/{routeRecovery,detailLoader,editorDraftSave}.test.js`
- `frontend/src/stores/editorDraftPersistence.test.js`
- `frontend/src/hooks/{useCourseDetails,progress,routeScrollRestoration}.test.js`
- `frontend/src/services/sessionContext.test.js`
- `frontend/src/utils/{sessionRecovery,reloadPersistence,uiPersistence}.test.js`
- `frontend/e2e/reload.spec.js`

Команды из `frontend/`:

```sh
npm test
npm run build
npm run test:e2e -- --reporter=line
```

Для стандартного окружения Playwright сначала нужен установленный Chromium (`npx playwright install chromium`). В текущем окружении использован уже установленный браузер, без скачивания:

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE='/Users/medvedevandre/Library/Caches/ms-playwright/chromium-1200/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing' npm run test:e2e -- --reporter=line
```

Браузерные тесты запускают настоящий Vite/React.StrictMode и подменяют API-контракт через Playwright route. Они проверяют прямые URL курса/модуля/урока/edit/metrics и варианты lesson/lessons, отсутствие курса на странице каталога, normal reload и reload с отключённым HTTP-кешем через CDP, немедленный reload после ввода, save/discard и повтор GET после 503. Это не live-backend E2E и не ручное нажатие клавиши F5.

Unit/lifecycle-проверки дополнительно покрывают управляемые задержки, ошибки API, истёкший access с валидным refresh, окончательно невалидную сессию, конкурентные изменения во время save, быстрые переходы, logout/login и A → B → A, corrupt/unavailable/quota storage, AI polling без повторного POST и DnD pagehide flush.

Фактические финальные результаты: `npm test` — 251/251 passed; `npm run build` — успешно; браузерная команда выше — 12/12 passed; `git --no-pager diff --check` из корня — успешно. У production build есть предупреждение Vite о крупных chunks; его оптимизация не относится к этой задаче.

## Ограничения

- **Критерий отдельного `/practice/:practiceId` полностью не закрыт.** В существующем backend нет GET отдельной практики по этому ID и нет поиска её родительского урока. Старый frontend route приводил к общему обзору курса; теперь вместо тихой подмены показано явное сообщение. Практика в поддерживаемой вкладке урока использует существующий механизм. Новый API и догадки о соответствии ID не добавлялись.
- Preflight GET не даёт атомарного optimistic locking между GET и PUT. Для полной межклиентской защиты backend должен поддержать revision/ETag/If-Match. CAS локальных snapshots также не является межвкладочной транзакцией.
- AI-сообщение, POST которого завершился на backend, но ответ с новым chat_id не дошёл до браузера, нельзя достоверно восстановить без серверного idempotency/history API. Reload его не повторяет автоматически.
- Прогресс профиля по-прежнему агрегируется по загруженной странице myCourses, не по всем страницам. Это не менялось в рамках reload-fix.
- Нет проверки с развёрнутым backend/реальными аккаунтами/LLM, Docker/nginx, Safari/Firefox и ручного длительного сетевого обрыва. Задержки и ошибки транспорта проверены управляемыми Promise/route fixtures. Прокрутка больше 15 секунд ожидания контента требует новой попытки пользователя.
- `npm install` сообщил об уязвимостях dependency tree; автоматический audit fix с изменением несвязанных зависимостей не запускался.

Изменения backend в рабочем дереве к этой задаче не относятся; не изменялись и не откатывались. Коммит не создавался.
